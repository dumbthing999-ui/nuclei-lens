# Reader exercise implementation candidate

Status: software preparation only. No recruited participants, consented sessions,
observations or human benefit. This dedicated offline exercise measures local
count decisions; it does not edit masks or replace the frozen scientific benchmark.

## Scope

Use four official BBBC039 training fields (positions3–6), with position8 for common
practice. Familiar demo positions1,2,7are excluded. These are development fields,
not independent biological validation. Real image suitability and participant
unfamiliarity still require review before sessions; retain difficult cases.

Six planned pseudonyms P01–P06 receive four distinct fields each, two per condition.
Odd/even assignments counterbalance order and field-condition allocation. Control
has baseline inspection and four seeded-hash tiles; assisted has the same controls
plus real alternatives and the four preselected object-disagreement tiles. Concrete
tie selection differs from the benchmark expected-tie capture convention.

## Separation

Generator reads pinned public archives and unchanged frozen inference/configuration.
Allowlisted served assets contain no annotations, reference counts, reference
metrics or benchmark dashboards. Source mappings, arm decoding and annotation
centroid counts live outside the served root. Scorer loads references after export.
This is hypothesis/reference blinding in the UI, not complete participant blinding
or an access-control guarantee for already public data/source code.

## Records and interpretation

Records retain four-tile entered counts, uncertainty/unresolved/aborted status,
completion time after assets load, visibility interruptions, task order, field/config
hashes and pseudonymous identity. Timing does not pause on tab visibility change;
interruptions are disclosed separately. Participant codes and client timestamps do
not independently prove human identity, consent or task behavior.

Tests use a visible synthetic mode and synthetic_test=true. Default scoring rejects
synthetic records; explicit software-validation mode labels its output synthetic.
No tests may be reported as real participant observations. Preserve all incomplete
and failed tasks; report participant-level descriptive paired outcomes with explicit
missingness rather than pooling tiles as independent people. No success threshold
or significance claim is introduced here.

## Before any real session

Review actual images, freeze the exact manifest/assignments/analysis before sessions,
provide equal practice and voluntary informed consent/retention choice, and confirm
any applicable review requirements. Do not recruit or message others without owner
authorization. The protocol is in READER_STUDY_PROTOCOL.md; tooling does not imply
that a study has occurred. No personal contact values or raw session files belong
in Git or public deployment.

## Outcome interpretation before sessions

Retain planned primary local-count MAE. Control and assisted select different
tiles, so raw final errors also reflect selection difficulty. Predeclare a
secondary same-assigned-tile baseline MAE and baseline-minus-entered error
reduction, alongside final MAE and completion/missingness. Do not replace the
primary outcome after seeing results, pool tiles as people, or use an AI-proposed
threshold to declare efficacy. Any tally calculation remains separate from mask
accuracy and downstream biological benefit. No observations have occurred.
